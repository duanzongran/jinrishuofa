# 央视剧集 + 今日说法 · FongMi / 影视仓 源

把央视网（tv.cctv.com）能抓到的电视剧，和《今日说法》历年节目，做成一个 App 里两个独立页面的点播源。

- 形态：**一个站点，两个分类页** —— 首页顶部切「电视剧 / 今日说法」，两套卡片各走各的，不混
- 体量：**电视剧 196 部 / 6209 集**（一剧一卡，无封面）；**今日说法 19 张年份卡 / 5450 期**（一年一卡）
- 播放：全部是央视网官方 m3u8 直链，**无签名、无加密**，不依赖任何解析器
- 更新：GitHub Actions 每天自动抓今日说法最新一期；跨年自动新建年份卡。电视剧目录不自动更新

## 一、推送地址

**配置地址（就这一个，填到 App 的「配置地址」里）**

```
https://ghfast.top/https://raw.githubusercontent.com/duanzongran/jinrishuofa/main/drama_config.json
```

> 只用这一份配置。`drama_config.json` 里的 `api`（也就是 `cctv_drama.js` 的取用地址）同样走 ghfast，两者同源，所以不要再手动改前缀、也不要另建配置副本——前缀和内部 api 一旦不一致，就会出现「站点能加载、卡片全空」。
> ghfast 是第三方公共中转，高峰期偶尔慢、偶尔无响应，属正常现象：等一会儿重试，或清缓存后下拉刷新即可。

**备份地址（gh-proxy 取同一份配置）**

```
https://gh-proxy.com/https://raw.githubusercontent.com/duanzongran/jinrishuofa/main/drama_config.json
```

> 这条取的文件和主地址**完全相同**，只是换了中转前缀，配置里的 `api` 依然指向 ghfast。
> 所以它只解决「ghfast 这一跳取不到配置」的情况；如果 ghfast 整体不可用（连 js 也拉不下来），这条同样会表现为卡片全空。无需改动它，留在文档里备用即可。

导入后：

1. 设置 → **清空缓存**（换配置必做）
2. 填配置地址 → 保存
3. 回到首页下拉刷新，出现站点「央视+今日说法」
4. 首页顶部应有 **「电视剧」/「今日说法」** 两个切换项

进「今日说法」→ 19 张年份卡 → 点某一年 → 这一年全部期数，按播出日期升序。

## 三、js 结构（`cctv_drama.js`）

```js
const HOSTS = ["https://newcntv.qcloudcdn.com", "https://hls.cntv.lxdns.com"];
const TPL   = "/asp/hls/main/0303000a/3/default/{guid}/main.m3u8?maxbr=2048";
const TV    = [ { id:"d001", name:"三国演义", remark:"全84集", eps:[ [集名, 主机索引, guid], ... ] }, ... ];
const JRSF  = [ { id:"y2026", name:"今日说法 2026年", remark:"201期", eps:[...] }, ... ];
```

- 卡片 id 带前缀区分：电视剧 `vod/d001`，今日说法 `jrsf/y2026`
- `homeContent` 返回两个分类；`homeVideoContent` 只吐电视剧；`categoryContent` 按 tid 分开分页
- 播放地址不存整串 URL，只存「主机索引 + guid」，一个地址从 ~100 字节压到 ~40 字节，5450 期才塞得进单文件

## 四、自动更新怎么跑

每日链路：

1. 取节目列表 `api.cntv.cn/NewVideo/getVideoListByColumn?id=TOPC1451464665008914&n=100&sort=desc&p={页}`
2. `guid` → `vdn.apps.cntv.cn/api/getHttpVideoInfo.do?pid={guid}` → 取 `hls_url`
3. **校验**：拉 m3u8 → 拉变体 → 拉首个切片，必须是真 TS（首字节 `0x47`、体积 >1500 字节），且无 `EXT-X-KEY`（加密的不要）
4. **换主机**：央视接口会随机下发坏主机（实测 `hls.cntv.cdn20.com` 直接返回 403）。校验不过就轮询两个正常主机，都不行则跳过这一期，不写坏地址
5. 按「播出日期 + 清洗后标题」去重，只追加；`2027` 这类新年份自动建一张新年份卡
6. 用 `tv_catalog.json` + 更新后的年份数据重建 `cctv_drama.js`，有变更才提交

历史数据里若混进坏主机，脚本每次运行会先修正一遍。

> 11.20 那期「当天新增打不开」的根因就是这个：旧脚本不管主机死活，抓到 `cdn20` 就写进去了。已修。

## 五、排查表

| 现象 | 原因 / 处理 |
|---|---|
| 站点存在但卡片全空 | js 没拉下来。前缀和配置里的 `api` 必须一致（当前都走 ghfast）；多半是 ghfast 临时抽风，过几分钟重试 |
| 只有「主页」，没有「央视+今日说法」 | 配置没被接受。确认仓库 **public**，清缓存重导入 |
| 首页没有「电视剧 / 今日说法」切换条 | 配置里 `filterable` 必须是 1；老内核可能不渲染 class |
| 某个年份卡点开是别的年份 | 老内核 bug。必须保持现在这种「同一 js 内分类过滤」结构，别再拆成多站点或多静态卡片 |
| 改完文件后 App 还是旧内容 | ghfast/raw 有几分钟缓存延迟，别立刻判失败 |
| 某一期打不开 | 该期央视侧下架或 guid 失效，不影响其他期 |
| 电视剧少了几部 | 早年按「必须集齐」规则剔过 21 部缺集 + 6 部短片伪剧，是故意的，不是丢失 |

## 六、踩过的死路（别再试）

1. **静态 JSON 多卡片**：网格正常，点任意卡详情回退到 `list[0]`（串成第一部）。
2. **多站点 type 3**：内核只加载 `sites[0]`，第二个站点永远不出现。这就是「今日说法做第二个站点」失败的原因，最终改成同站点双分类。
3. **`aka.doubaocdn.com` 临时 CDN 托 js**：对 `.js` 返回 404，FongMi 拉不到 → 卡片全空。必须放 GitHub raw。
4. **`hls_h5e_url`（`dh5ws01.v.cntv.cn`）**：是真 TS，但 FongMi 会丢弃这种条目，表现为「集数变少」（亮剑 26 集只剩 22）。
5. **`/asp/enc/hls/`**：能播但黑屏（加密壳），一律不用。
6. **坏主机 `hls.cntv.cdn20.com` 等**：403。必须归一化到两条正常主机。
7. **短片冒充正剧**：专辑页里的「剧情速览」每集只有 2–3 分钟，按 `video.totalLength` < 15 分钟判为非正剧，整部剔除（已剔 6 部）。
